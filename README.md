# React client for MAX through GREEN API

Тестовое задание фронтенд-разработчика. Автор: Роберт Аглямов.

Простой интерфейс в стилистике веб-чата MAX: подключение GREEN-API, создание диалога по телефону, отправка и получение текстовых сообщений. React и TypeScript, без собственного сервера и без сторонней UI-библиотеки.

## Локальный запуск

Нужен Node.js 24.15+ LTS либо 22.22.2+ LTS; версии зависимостей зафиксированы в `package-lock.json`.

```sh
npm ci
npm run dev
```

Откройте Local URL, который напечатает Vite. Сервер слушает только `127.0.0.1`.

```sh
npm test
npm run build
npm run preview
```

`dist/` — самостоятельная статическая сборка для HTTPS-хостинга. Никакие ключи не подставляются во время сборки. Демо открывается отдельной кнопкой и не делает API-запросов.

## Реальная переписка

1. Подготовьте **отдельный тестовый инстанс MAX** в GREEN-API. Авторизуйте его в своём кабинете. Не используйте очередь рабочего бота или CRM.
2. В кабинете включите входящие уведомления, используйте получение через HTTP API, без `webhookUrl`. Приложение читает состояние/настройки и не меняет их автоматически. Другие потребители очереди должны быть остановлены.
3. Укажите `apiUrl` своего инстанса, `idInstance` и `apiTokenInstance`. apiUrl берётся из кабинета, а не вычисляется по idInstance. Разрешены только HTTPS-хосты GREEN-API.
4. Подтвердите, что это отдельный тестовый инстанс. После обработки уведомление **безвозвратно удаляется из очереди** вызовом DeleteNotification. Неподдерживаемые события тоже подтверждаются, но не показываются в текстовом UI.
5. Создайте чат по номеру РФ или Беларуси. CheckAccount преобразует телефон в канонический MAX chatId. Если аккаунт не найден/скрыт, фиктивный чат не создаётся.
6. Отправьте текст выбранному тестовому получателю. Попросите его ответить в MAX. Ответ отобразится в этом диалоге через ReceiveNotification.

Браузер делает запросы прямо к GREEN-API. Если сервис/сеть блокирует CORS, потребуется согласованный серверный proxy; обход CORS и открытые сторонние proxy не используются.

## Безопасность и поведение при сбоях

- Токен и история существуют только в памяти текущей вкладки; нет localStorage/sessionStorage, аналитики или логирования секретов. Выход очищает сессию, обновление страницы тоже. В frontend-прототипе токен всё равно доступен пользователю через DevTools — для production с несколькими пользователями нужен backend.
- Токен передаётся в пути запроса по контракту GREEN-API; внешние редиректы запрещены, credentials/cookies не отправляются, сырые ошибки с URL не выводятся. Не публикуйте HAR с реальным токеном.
- Один последовательный long-poll; отмена при выходе/размонтировании, backoff при временных ошибках, остановка при неверной конфигурации/авторизации.
- Сначала обработка сообщения, затем ACK. Если ACK временно не удался, повторяется ACK, а не обработка. Повторные idMessage не дублируют сообщения в пределах сессии.
- Успех SendMessage означает **«Принято API»**, не доставку адресату. Доставка/прочтение меняются только по статусным событиям. Если статусные уведомления выключены в кабинете, останется «Принято API».
- При сетевом сбое/5xx отправка может уже состояться. Статус «Исход неизвестен», автоматического повтора нет. Перед ручным повтором проверьте MAX.
- После ACK история остаётся только в памяти: это минимальный прототип, не долговременный архив переписки. Для production нужны хранение и согласованная политика retention.
- Текст выводится как текст React, без HTML-вставки. Поддерживаются переносы, Enter и Shift+Enter. Лимит UI — 4000 символов.

## Устройство проекта

- `src/api.ts` — проверка входных данных и HTTP-адаптер GREEN-API.
- `src/polling.ts` — последовательная очередь receive/process/ack.
- `src/model.ts` — состояние, дедупликация, маршрутизация и статусы, включая события раньше ответа POST.
- `src/demo.ts` — отдельная in-memory симуляция, не подмена реального API.
- `src/App.tsx` — React-интерфейс и жизненный цикл сессии.
- `src/*.test.*` — контрактные тесты с подменой fetch, состояние, очередь и пользовательские сценарии.

Для создания и проверки использовался Codex. API-контракты сверены с официальной документацией; демонстрация и контрактные тесты не заменяют реальную проверку на авторизованном MAX-инстансе.
